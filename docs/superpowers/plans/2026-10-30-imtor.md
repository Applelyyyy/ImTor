# ImTor Implementation Plan

> For agentic workers: use superpowers:subagent-driven-development for isolated frontend and infrastructure tasks; integrate and review all changes before completion.

**Goal:** Build and verify the full-stack ImTor application described by the supplied specification.
**Architecture:** One Next.js App Router deployment, PostgreSQL/Prisma services, Google authentication and S3 uploads. Server components read shared services and REST handlers authorize all writes.
**Tech Stack:** Node 24, Bun, Next.js 16, React 19, Prisma 7, PostgreSQL, NextAuth v4, Tailwind, shadcn, Zod, Vitest, Playwright, Docker.
**Spec:** docs/PRODUCT_SPEC.md and docs/superpowers/specs/2026-10-30-imtor-design.md.

## Global constraints
Thai user interface, English developer docs. All P0 requirements, no fake APIs, no hardcoded university or domain, no genuine records removed by demo cleanup. No public deployment without authorization.

## Review focus

## Execution ledger

- Foundation: implemented and migrated on isolated local application/test PostgreSQL databases. Stable NextAuth v4 was selected instead of v5 beta; no fake demo authentication was introduced.
- Marketplace/merchant/admin: implemented, typechecked and browser-tested against actual APIs/database. Independent UI and infrastructure agents used non-overlapping files; root integrated shared contracts.
- Engines: RED→GREEN pricing, recurrence, cancellation, byte validation, stock/stall transactions and safe demo cleanup. Final suite contains a page-level authorization boundary regression.
- Review corrections: malformed discount, category bootstrap, cancellation editing, schedule-reader race, rendered expiration and immutable impact mode snapshots.
- Additional runtime correction: a production-container negative control found layout-only RSC data leakage. Added per-page authorization before private queries; raw marker regression failed before and passed after. Final container matrix passed 60/60 checks.
- Infrastructure: four actual migrations, non-root standalone and migration images, Compose startup/health, backup/restore and confirmation/retention/corruption controls passed on task-owned local resources.
- Local Playwright: 13 complete scenarios passed; three additional admin UI scenarios and separate guest/non-admin raw-stream checks passed. A stale checkbox test selector was corrected after unique accessible form IDs were introduced; full rerun passed.
- External boundaries: real Google callback, remote R2/AWS, actual campus coordinates/schedules, domain DNS/TLS and public deployment are not verified or claimed.
- Final performance/accessibility review: Lighthouse observations are recorded in VERIFICATION.md; scores are measurements, not assumed gates.
